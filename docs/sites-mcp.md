# 用 Sites 部署远程 MCP

更新日期：2026-10-04

适用：在官方 ChatGPT 中已经能使用 Sites 的账户。菜单可能显示“Plugins／插件”或“Apps／应用”，功能受账户、工作区权限与灰度影响。

## 先记住这一条

**让 Sites 托管一个远程 MCP 服务，发布后连接它配套的私有插件，再在对话里调用工具。**

最简单的工具可以全部运行在 Site 上。若数据和核心服务在自己的服务器，Site 只做协议与权限适配：

```text
ChatGPT
  → Sites 配套插件与平台认证
  → Site 的 POST /mcp：校验用户、参数与工具白名单
  → 可选：自己的 HTTPS 窄网关
  → 私有核心服务／数据
```

部署 MCP 不会自动把原有数据搬到 Site，也不会自动产生外部消息唤醒、Webhook 或后台定时任务。那些是独立功能，需要另行配置。

这是远程 MCP 路线；网页里的 WebMCP、电脑上的 stdio 服务和本地 MCP 配置是不同接入方式。官方远程插件文档要求可达的 HTTPS MCP 端点，并验证初始化、工具定义和认证。[远程 MCP 连接说明](https://developers.openai.com/plugins/deploy/connect-chatgpt)

## 1. 先用一个只读工具跑通

在官方 ChatGPT 中提到 `@Sites`，也可以明确说“创建一个网站并用 Sites 托管 MCP”。已有 Site 就明确要求打开并修改原 Site，别重新建一个相似项目。

可以直接复制这段提示词：

> 请用 Sites 创建一个私人 MCP 服务。先只提供一个只读 ping 工具，返回固定的非敏感状态。
>
> 在项目根目录的 .openai/hosting.json 中保留现有配置，并把 mcp 加入 capabilities。实现适配当前 Sites 服务端运行时的无状态 HTTP POST /mcp，支持 MCP initialize、tools/list、tools/call；不要使用本地 stdio 或本地 MCP 配置。
>
> 使用 Sites 提供的认证及配套 App／私有插件，不另建 OAuth 流程。发现结果不包含私有数据；有数据的调用必须在服务端检查用户与权限，未授权返回 401 或 403。
>
> 先检查和保存版本，再私有部署。等部署明确成功后，给我 Site 链接和配套插件的安装／连接入口。连接后真实调用 ping 验证，不以“已列出工具”代替调用成功。不要把任何密钥放进代码、聊天或前端。

配置的关键只是**合并**这个能力，不能整份覆盖原文件：

```json
{
  "capabilities": ["mcp"]
}
```

这不是完整项目模板。原来的 `project_id`、其他能力与存储绑定都要保留，由 Sites 的正常创建／打开／保存／部署流程管理。服务端产物也必须兼容 Sites 运行时，不能假定任意 Node 常驻进程都能直接搬进去。

Sites 可从对话创建、继续编辑与部署；网页端可从 More → Sites 进入。每个部署链接都是生产版本，想先审核就明确要求“保存但不部署”。[Sites 官方操作说明](https://learn.chatgpt.com/docs/sites)

## 2. 连接 Site 自带的插件

让助手读取 Site 的 MCP 连接信息，展示平台提供的安装／连接入口。手动找时，可查看 Plugins → Personal → Created by you，打开该 Site 的插件并选择 Install／Connect；中文菜单以实际界面为准。

**继续更新同一个 Site，复用配套 App 与私有插件。** 这条路线不需要再创建一套自定义 App，也不需要运行 `codex mcp add` 或 `codex mcp login`。

连接后开一个测试对话，选中或 @ 提到该插件，要求调用 ping。验收要看到真实工具结果，而不是助手用文字说“应该通了”。

## 3. 再加实际业务工具

每个工具至少写清：

- 名称、用途、什么情况下不能调用
- `inputSchema`，必要时声明 `outputSchema`，并校验参数
- 返回结构、空结果、分页与错误语义
- 真实的只读／写入／删除／外部访问属性

只读工具标记 `readOnlyHint: true`。不删除或覆盖数据的工具可标记 `destructiveHint: false`；访问开放互联网的工具与仅访问固定私有账户的工具，`openWorldHint` 应按实际范围区分。这些标记不能代替服务端授权。[工具元数据说明](https://developers.openai.com/plugins/guides/optimize-metadata)

推荐迭代顺序：

1. ping 验证接入
2. health 验证配置与依赖，再逐项接入业务工具
3. 工具成熟后移除临时 ping，保留不会泄密的 health
4. 长记录做只读分段查询，例如 resume：使用 cursor／limit；需要整份结果时由后端组装，避免一次塞进对话

“health + 15 个业务工具”可以是一版实例，**15 不是平台固定数量**。若 health 严格检查目录数量，新增或删除工具时必须同步预期数量；最好同时比较工具名称集合。不能因为数量匹配就宣称所有工具都正常。

业务失败要返回可识别的错误，不能伪装成空数据或成功。写入工具先确认目标与影响；超时后先查执行状态，不自动重试写入，避免重复创建、发送或扣费。

## 4. 私有后端可选：只开一个窄网关

如果业务在 VPS，上面架构中的 HTTPS 网关只负责固定工具到固定后端动作的映射：

- 仅允许明确列出的工具、方法和参数；设置超时、请求大小与速率限制
- 不提供任意 URL 转发、任意路径读取、通用 shell 或“透传所有管理接口”
- 保留原有核心服务的私有入口，别为接入 MCP 把整个管理端公开
- 网关用独立、可撤销、最小权限的凭证；不要复用核心服务管理员 token
- 日志只记请求标识、工具名、耗时和结果码，隐藏 token 与私有内容

Sites 在认证边界提供可信身份头，包括 `oai-authenticated-user-id`、`oai-authenticated-user-email` 与可选显示名。服务端据此检查目标用户；显示名不能作为权限依据，也不能信任公网请求自行伪造的同名头。若自己的后端有多用户权限，还要保持各用户授权隔离。

密钥由用户通过安全界面填写。建议在本机用密码管理器或加密随机生成器产生至少 32 字节的独立 token，分别放入 Site 的 secret 与 VPS 的安全配置，不在聊天回传。前端包、网页源码、Git、构建产物和公开日志里都不能出现密钥。

Site 中可用 `GATEWAY_BASE_URL` 作为普通配置、`GATEWAY_TOKEN` 作为 secret；这里只是键名示例。Sites 的环境值在 Site 设置中管理，不写进 `.openai/hosting.json`。修改后重新部署并验证实际运行版本，别只检查设置页面。[Sites 环境变量与秘密值](https://learn.chatgpt.com/docs/sites#configure-runtime-environment-values)

## 5. 更新工具后，分清三层

**源码已改 ≠ 线上已部署 ≠ 当前对话已发现新工具。**

先确认正确 Site 的正确版本部署成功，再检查线上 `tools/list`，最后检查 ChatGPT 实际可见目录。

开发模式连接：官方流程是部署服务 → 连接详情选择 Refresh → 确认元数据变化 → 新对话重测。已发布插件的工具更新走持续审核；插件资料或导入的技能变更可能需要新版本、审核与发布。不要承诺刷新一次就立即生效。[插件连接与刷新](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata)

Site 托管源码与自己的上游仓库也要分清。改好了 Site，不代表代码已同步到某个个人公开仓库；需要同步时单独检查仓库、分支与提交，并另行确认公开范围。

## 6. 最后验收与回滚

上线前逐项打勾：

- [ ] initialize、tools/list、至少一个真实只读 tools/call 成功
- [ ] 工具名称、数量、参数及返回结构与本次版本一致
- [ ] 未登录／错误用户不能读取私有数据
- [ ] 正常、空结果、非法参数、超时、分页都测过
- [ ] 写入有明确授权边界，失败后不会重复执行
- [ ] 源码、前端、日志和工具发现结果不含秘密值或私人标识
- [ ] 记录上一个可用部署版本；必要时重新部署该版本并重测目录
- [ ] 回滚代码后仍检查密钥和后端配置，它们不一定随版本回滚

常见问题：

- **工具列出来了，调用却 Unauthorized**：发现成功不能证明数据权限正常。分别检查 Site 用户授权、网关凭证和后端权限；不要临时关认证
- **仍看到已移除工具／看不到新工具**：检查部署版本与线上目录，再走对应刷新／审核流程，新对话重测
- **token 看着一样仍失败**：检查前后空格、换行、引号和两端配置；不要把 token 打到日志排查
- **改配置没有变化**：确认运行时引用的是正确键、正确 Site，并重新部署
- **health 数量报错**：同步预期目录；数量不是权限或业务成功的证据

工具接入完成后，继续读 [Sites 接入自建后端](sites-setup.md)，再按 [完整指南](guide.md) 增加事件唤醒、上下文与记忆传递、回复回流。
