# 验收清单

先用虚构数据检查代码和接口，再在用户批准的会话中发送一条真实短消息。目录连通、平台接收事件、官端回复和本地接续是不同的成功阶段。

## 前端和权限

- [ ] 当前实际使用的页面有官端设置入口。
- [ ] 输入 `@` 后点选才产生明确的发送对象；单纯粘贴或引用不路由。
- [ ] 编辑标签、取消、输入法、换窗和发送后清空都正常。
- [ ] 手机宽度下入口与输入框可用。
- [ ] 后端验证发送对象与文字匹配，只接受授权会话。
- [ ] 真实令牌、票据、callback 和私人材料不进入公开日志或前端构建包。

## 配对和订阅

- [ ] 用户选择目标窗口，私密提交短期配对指令。
- [ ] 平台提供 callback 和签名秘密，服务端验证地址与签名 challenge。
- [ ] 验证完成且事务成功后，绑定状态才变成已订阅。
- [ ] 订阅持久保存、到期可续；重启后状态仍正确。
- [ ] 改绑、过期或撤权后，旧请求和迟到回复不能越权。

## 材料和记忆

- [ ] 触发消息在快照里只有一次，顺序、角色、来源和附件身份保留。
- [ ] 最近十轮按项目的对话分组规则计算，连续气泡不会被误算成固定十条。
- [ ] 同一请求最多发起一次召回；失败、结果未知、成功零命中分别记录。
- [ ] 记忆服务不额外塞入第二份最近对话。
- [ ] 事件只带请求引用，不带聊天正文。
- [ ] `get_request` 每页只携带一种正文表示，且不同时在文本和结构化结果中重复打印正文。
- [ ] 大材料读取至 `complete`，按顺序拼接，原始 UTF-8 字节摘要匹配。
- [ ] 中文、emoji、附件元数据和浮点数表示保持完整。
- [ ] 附件对目标窗口真实可读，失效或私网地址有明确处理。

## 回写和可选接续

- [ ] 官端能被事件自动唤醒并读完材料。
- [ ] `reply` 的请求、事件、订阅和绑定版本关联一致。
- [ ] 同一请求保存一次最终回复，稳定 `reply_id` 重试不产生新气泡。
- [ ] 前端依据服务端回执显示官端来源。
- [ ] 原生模型忙碌时排队，空闲后处理，无需再发一句人类消息。
- [ ] 同线程已存在的原话不再次灌入；可信后继窗口只补未送达材料。
- [ ] 唤醒把原消息和官端回复标成历史材料，不把原话作为新的当前指令。
- [ ] 已确认未提交的失败可重试；已发送但结果未知时不自动重发。
- [ ] Silence 不产生空白气泡；回流消息不会再次触发官端。

## 记录结果

记录状态、数量、耗时与错误分类即可。不要为验收打印真实消息、记忆、票据或秘密值。

| 层次 | 需要的证据 |
| --- | --- |
| 代码 | 使用虚构数据的检查通过 |
| 部署 | 运行版本与目标 Git 提交一致 |
| 目录 | 官端实际看到正确工具和事件 |
| 平台投递 | 已接收签名事件 |
| 官端处理 | 已读完材料、生成并回写 |
| 自建聊天 | 官端回复保存并显示一次 |
| 可选原生接续 | 原线程实际处理，产生回复或正确 Silence |

仓库里的 JSON 只能说明字段关系，不能替代你自己的真实链路验收。
