# Sites 接入自建后端

这一步让官端能调用你的后端。Site 负责平台接入和访问控制，自己的后端负责聊天、记忆和业务状态。完成工具接入后，再按[完整指南](guide.md)实现事件唤醒。

## 准备接口

准备自己的 HTTPS 业务入口，例如 `https://bridge.example.invalid/mcp`。这个地址只是占位示例，必须换成你自己的可用接口。

服务只处理允许的 MCP 方法和业务工具，检查身份、参数及请求范围。Site 转发地址固定在服务端配置里，不接受调用者传入任意 URL。

你需要分别检查两段权限：访问 Site 的平台用户有权使用它；Site 使用专用凭据访问自己的后端。前端只提交聊天和明确选择，不持有后端服务令牌。

## 建立私有 Site 和 MCP 入口

可以把下面的需求交给支持 Sites 的开发助手：

> 请建立一个私人 Site，作为我自建聊天后端的 MCP 适配层。复用 Site 配套的私有插件，在服务端暴露 POST /mcp，支持工具目录与调用，并按官方 MCP Events 文档处理事件目录和订阅。上游业务地址固定在服务端，检查平台身份和访问权限。目录中不包含私人内容。后端访问令牌从 Site 的 Secret 环境变量读取，不写进源码、提示词、前端或 hosting.json。先部署只读准备状态，完成目录检查后再正式启用。具体业务契约见本仓库指南。

Sites 的部署流程、构建文件和插件连接应由当前 Sites 工具完成。成功发布后，还要在目标 Work 中确认实际连接可用；发布成功与订阅成功分别验收。

## 配置令牌

在 Site 的私密设置里保存专用后端令牌，保持 Secret 开启。本教程约定示意名称为 `CONTEXT_BRIDGE_MCP_TOKEN`，你的实现必须使用相同键名读取。

令牌应通过设置界面输入。不要把真实令牌发给助手、附在文件中，或写进公开仓库。修改 Site 环境变量后，需要重新部署，让运行版本使用新配置。[Sites 环境配置说明](https://learn.chatgpt.com/docs/sites#configure-runtime-environment-values)

其他配置名称由项目自行约定。可使用 `preparation` 和 `ready` 区分只读检查与正式业务；它们是本教程的实现选择。

## 先查目录再配对

1. 在关闭或准备状态下，检查鉴权失败是否正确拒绝。
2. 检查 `server/discover`、`tools/list`、`events/list` 的实际响应。
3. 确认目录只有批准的业务能力，并声明 Events。
4. 准备状态只允许必要的只读检查，不能意外创建成功订阅或读取聊天。
5. 正式开启后，由用户在目标 Work 中完成私密配对。

单独的 HTTP 200 不足以证明成功，还要看 JSON-RPC 是否有 `error`。同样，后端已返回 `ready` 时，Site 的只读准备检查不应仅因状态比预期更完整而误报故障。

## 更新后检查实际能力

变更工具名称、说明或 schema 后，确认部署版本和目标 Work 实际看到的目录。开发模式连接可按官方 Refresh 流程更新元数据；已发布插件的工具更新机制不同。[连接与更新说明](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata)

用户看到的插件入口和权限取决于当前产品界面及工作区策略。遇到差异时以实际界面和官方说明为准。
