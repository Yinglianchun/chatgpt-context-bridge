# 常见问题

## 最近对话取多少

教程采用最近十轮。按连续角色片段分组，一轮可包含连续多条消息，所以不固定等于二十条。需要在自己的后端明确轮次定义。

## 官端会自己读取记忆吗

不会因接入事件就自动获得你的记忆库。后端先按触发消息做一次检索，再把返回材料放进请求快照。`ok` 且零命中与召回失败要分开记录。

## 原话会重复送入吗

同一请求的触发消息在快照中只出现一次。事件只通知请求编号；工具结果只带一种正文表示。旧的解析快照字段可以保留为空，兼容已有消费者。

如果原生模型自己发起官端请求，原话已在同一线程的历史中，回流应跳过它。换窗后，只有受信任的后继线程还没收到时才补入，并保留原消息身份。这依赖自己实现的送达回执。

## 发给官端的话会被本地模型当成当前指令吗

明确选择官端后，后端停止那条消息的普通本地自动回复流程。官端回写时再唤醒本地模型，并把原话与回复作为有来源的对话材料送入。新的唤醒提示要明确说：这是官端回应事件，不是用户又说了一遍。

原角色、来源和收件对象是历史数据，不能转换成新的 provider 消息角色或继承新的发送授权。

## 为什么有工具却没有自动唤醒

工具接通与 Events 接通是两步。检查事件能力、目录、目标 Work 的订阅、callback 验证、订阅到期时间和实际投递状态。

## 为什么事件已接收却没有回复

接收成功表示平台接收了事件，不能证明已经完成生成或回写。继续查目标窗口是否读完材料、是否调用 `reply`，以及关联字段是否正确。[官方投递说明](https://developers.openai.com/plugins/build/mcp-events#handle-delivery-responses)

## 为什么分页摘要不一致

对完整 `snapshot_json` 或拼接后的 `snapshot_json_part` 原始 UTF-8 字节计算摘要。解析再序列化可能改变数字表示、空白或转义，导致摘要不同。

## 准备阶段返回 500 怎么查

分别检查部署版本、HTTP 状态、JSON-RPC 错误和后端准备状态。我们遇到过后端已 `ready`，Site 却仅接受另一准备状态；也遇到错误发生在 SDK 服务创建阶段，外层只显示 500。保留脱敏错误分类，再定位具体层次。

## 旧 CLI 是不是必须升级

CLI 不参与所有部署方案。只有可选原生接续需要它时，才检查实际历史读取和提交协议。旧版本可能读不全分页历史，也可能需要文本映射适配；升级后仍要验收完整历史与提交回执，不能把升级本身当成成功。

## 能不能靠识别正文里的 at 符号路由

教程要求独立的明确选择对象。普通正文、引用和粘贴中的 `@` 都是文本。后端还要校验文字范围与选中标签是否匹配。

## 可以直接运行这个仓库吗

这是纯教程。JSON 使用虚构数据，展示契约形状。部署自己的系统时，需要实现存储、权限、配对、投递、工具回写及所选运行时的适配。
